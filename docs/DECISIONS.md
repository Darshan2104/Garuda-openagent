# Garuda — Major Changes

What was broken, what we did, what it bought us. 2026-06-30 → 2026-08-01.

Numbers come from the commit that made the change. Anything marked *1 trial* is a
direction, not a result — this task suite is noisy and nothing has been run twice.

| What was wrong before | How we fixed it | Impact |
|---|---|---|
| `Message` had no `tool_calls` field, so the assistant's tool-call turn was stored as plain text. The next turn sent tool *results* with no call to attach them to — an invalid sequence the provider rejected. | Store and serialize `tool_calls`; add a provider-conformance test suite that validates payload shape with no live provider. `c94b9ed` | Multi-turn tool use worked at all. Tests 49 → 93. |
| Truncation notes and steering nudges were appended the moment they were computed — sometimes *between* an assistant tool-call message and its results. Invalid sequence → HTTP 400 → run aborts. The harness's own helpfulness killed runs. | Queue nudges and flush them at the top of the next turn, so call/result blocks stay contiguous. `7fbdde8` | Removed the highest-severity failure class we found: a dead run, not a degraded one. |
| A generic `APIError` carrying a transient 429 or 503 was treated as fatal, so one bit of provider weather ended a long run. | Retry transient statuses (408/409/425/429/5xx/520–524/529); fail fast on 400/401/403/404 and context-window errors. Honour `Retry-After` (cap 60s), jittered backoff, retries 3 → 5. Streaming falls back to non-streaming mid-stream instead of returning a partial answer. `3fba368` | Long runs stopped dying on rate limits. |
| A failed HTTP MCP connect raised `CancelledError` — a `BaseException` — so it walked straight through the `except Exception` that existed to contain it, and crashed the run. | Explicit `except asyncio.CancelledError`, re-raising only on genuine self-cancellation. Plus handshake timeouts and per-server fault isolation: skip the broken server, don't abort startup. `632f71d`, `30e1b67` | One bad MCP server can no longer take down a run. Caught in live testing, not review. |
| The LLM completion judge **approved** both when its model call errored and when the verdict was unparseable. A gate that opens when it breaks is not a gate. | Fail closed: retry once, then reject on error; reject on unparseable verdict. Structured JSON `{verdict, reason}` with prefix fallback. Made opt-in, since it costs a call. `2a53e79`, `632f71d` | The verdict became a real gate. Deterministic checks stay on by default. |
| `verification_commands` ran unbounded with no exception handling — a watch-mode test hung the completion gate forever. | 300s timeout inside `try/except`. `7fbdde8` | No more indefinite hangs at the finish line. |
| The contract gate refused *before* running any verification command, yet still filed those commands as "rejected". On the next attempt the resubmit guard saw the same commands and refused with "presents no new evidence" — so an agent that did exactly what it was told was locked out, with no escape but inventing a command it never needed. | `record_contract_rejection` counts the rejection and keeps the feedback but records **no** command set. The verification path still records commands, because that verdict did judge them. `1c21344` | 4 of 16 tasks had been burning all 60 turns reporting failure while the grader scored their work 1.0. `fix-docker-python-dependency-conflicts`: 60 → **15 turns**, `agent_success` false → true. The 7 "no new evidence" rejections → 0. |
| The evidence classifier split commands without tracking quotes, so it misjudged in both directions: `python3 -c "import csv; print(1)"` graded as real execution (guard bypassed), while `echo "run x && grep -q y"` graded as an assertion. Three of four tasks were approved and scored 0.0. | Quote-aware splitting; grade a `python -c` one-liner by whether anything in it can raise **because a value is wrong** (imports/prints = weak, `assert`/`raise` = strong, a bare call still runs the deliverable). Rejection feedback now names the fix. `98c08aa` | Both exploiting tasks were caught; `train-fasttext` came back with a real `assert` on tensor shape. 19 existing classifier cases unchanged. Honest ceiling: the gate can check an oracle *can* fail, never that it is the *task's* oracle. |
| `verification_commands` was documented as "optional commands to run before accepting completion" — nothing told the model what makes one worth offering. | Ask for commands whose **exit status would change if the work were wrong**, with a self-test ("if the answer is 'still exit 0', it is not verification"). Placed in the shared tool contract, not a profile prompt — a profile prompt *replaces* the default, so guidance in `harbor.yaml` would reach only the benchmark profile. `77c5c41` | *1 trial, 4 tasks:* deliberation at the completion turn 1/4 → 3/4 tasks, assertion share of evidence 17% → 27%, wall-clock −16%, cost +17%. Reward unchanged at 1/4. |
| Compaction destroyed data that was still on disk: pruning a bulky tool output replaced it with a generic "re-run the tool" stub, killing the `buffer:<id>` pointer, and full summarization dropped whole messages irretrievably. | Keep the retrieval pointer when pruning; buffer un-buffered outputs *before* stubbing them; diff history around **any** condenser run and archive dropped messages to a greppable `archive_*` buffer, annotating the summary with its id. `3d53360`, `c89a453` | Compaction became lossy in context, lossless on disk. Buffers are host-side, so recovery works the same under local, Docker and remote. |
| The compaction gauge measured the **message list, not the request** — missing tool schemas entirely on the cold path, which is turn 1 and after every compaction, exactly when the window is tightest. It also ran a full tokenizer pass on every read. (Two earlier versions of this bug: the trigger was turn count, then provider usage that lagged a turn behind large tool outputs.) | `count_request_tokens()` on the model protocol with a free-function fallback. Count JSON tool arguments, echoed reasoning and images — each omission was a systematic undercount, and an undercount overflows where an overcount merely compacts. Anchor + delta accounting: one full count per compaction, not per call. `capacity()` subtracts reserved output. Re-check the budget immediately before `model.complete`, after nudges land. `1df4617` | The harness's own budget view became visible per turn (a `BUDGET` event) and correct. |
| `AgentConfig.max_tokens` had exactly one consumer — the output reserve — and was never sent to the provider. Setting it *dropped the reserve* while leaving the response free to exceed it, so the config that reads as tightening the budget made it strictly less safe. | Send it on the turn's model call; make it authorable from YAML/`.md` profiles like every other knob. `519cac7` | The knob now does what its name says. |
| `ContextWindowExceededError` is correctly non-retryable in the client, but nothing in the loop handled it — so a fully recoverable condition was reported as a dead model and ended the run. | Translate to a provider-agnostic `ContextOverflowError`; force-compact and retry **once** — a different, smaller request, not the same one twice. Re-raise honestly when nothing can be dropped, and record the cost of the attempt. `519cac7` | Window overflow became recoverable instead of terminal. |
| We trusted litellm's token count as ground truth. It has no real tokenizer for `minimax-m2.5` and read a 3,623-token prompt as 2,530 — 30% low, concentrated in the tool schemas. | Take the **higher** of the provider tokenizer and our own estimate; learn a fixed local-count shortfall from the provider and apply it only to full re-counts. Output reserve set to 16k from measurement, not taste. `519cac7` | Turn-1 error **−24.6% → +4.7%** (an overcount, which compacts early, instead of an undercount, which overflows). Gauge median error vs provider `prompt_tokens` across 4 live runs: **0.6%**. Reserve justified by 4,315 real responses: max output 8,391, so an 8k reserve is breachable. |
| Profile defaults repeated the reserve/threshold literals instead of reading them off `AgentConfig`. The duplicated copies won, so retuning the reserve changed nothing that actually ran. | Read profile defaults off `AgentConfig`. `519cac7` | Killed a whole class of "I tuned it and nothing happened". Found only by reading the value back off a live run's budget event. |
| After a compaction the model re-derived what the harness already knew — the goal, the todo list, which files it changed, what verification passed. Todos were stored but never re-surfaced. The summarizer spent an LLM call paraphrasing a file list we had exactly. | A **working-state card**: structured state the harness owns, assembled from the side-effect ledger, the goal/todo tools and the contract, plus bash exit codes filtered through the evidence classifier. Re-pinned as one message, checkpointed to `state.json`, handed to the summarizer as given fact. Re-pinning made idempotent, since a prune-then-summarize sequence had produced three copies. `1df4617`, `519cac7`, `584db6d` | The summarizer's call now buys findings and dead ends instead of a paraphrase of facts we can state exactly. |
| A tool result's byte budget was a fixed number and truncation was head-heavy — so a traceback lost the part that says what failed. | Scale the budget with remaining context, floor it higher for errors, truncate errors tail-heavy. Under pressure, move output into the buffer (lossless, greppable) rather than truncating. The adaptive budget may only tighten a configured threshold, never loosen it. `1df4617` | Less information lost exactly when the run is under pressure. |
| Subagent handoff was all-or-nothing (whole transcript or nothing), and `fork()` **shared the condenser instance** — so a fork's compaction would overwrite the parent's running summary state. Reconstructing it via `type(c)()` reset tuning and raised `TypeError` for any strategy with a required argument. | `fork(mode="none"｜"brief"｜"full")`; `brief` passes the state card plus retrievable buffer ids. Deep-copy the condenser, then clear conversation-specific state via an optional `reset()`. `brief` degrades to `none`, never to `full`. `1df4617`, `519cac7` | A cheap middle handoff option, and a latent bug that would have taken every subagent down with it. |
| Repetition was reported once per *consecutive* repeat. A stuck `[read, read, write]` cycle yields `a, b, w, a, b, w` and never repeats consecutively — so the commonest mixed stuck pattern went entirely unseen. | Report repetition once per response. `519cac7` | The loop can now see the stuck pattern that actually happens. |
| Against opencode on the same 17 tasks, same model and provider, we cost **1.67×** more ($1.43 vs $0.86) at near-identical solve rates. Our context handling, caching and verbosity were all *better*; the difference was model calls (883 vs 545) and completion tokens (286k vs 76k). The single largest contributor: 229 `contract` tool calls, **every one carrying exactly one mark**, against ~15 criteria per task — pure bookkeeping, one round-trip per criterion, and nothing in the loop required it. | `mark_many` resolves a list of marks in one call, with partial application so one malformed entry doesn't force a full resend. Prompts and the tool description say to batch. `bc4ae83` | *4-task sample:* contract calls **79 → 6**, model calls 201 → 108, cost $0.348 → $0.145. Same evidence discipline per criterion — only the turn cost changed. |
| The loop had one fast path: if a response contained *only* read-only calls, run them concurrently. One write anywhere forced the whole response sequential, so `[R R W R R B]` was six sequential calls. Read fan-out was also unbounded — twenty reads opened twenty at once. | Split a response into contiguous read-only / not-read-only segments. Contiguity is the safety argument: a read before a write still runs before it. Bound fan-out by `max_parallel_reads` (8). Independent verification reads gather via a separate fail-closed allowlist; stability re-checks stay serial because they re-run the commands that write. `1df4617` | Fewer wasted round-trips per response, with the ordering guarantee intact. Fixed two latent bugs: parallel reads returned bare counts, so neither attached images nor the repetition steer was reachable. |
| The side-effect-free allowlist admitted `sort`, `uniq` and `cut` — all of which name an **output file as an argument** with no redirect to notice, so `sort -o merged.txt` could race a write against a concurrent read of the same file. And a bare `&` only counted as mutating when trailing, so `cat a & rm -rf build` was graded side-effect free. | Drop the three commands (special-casing `-o` needs per-command flag arity, which is exactly the parsing that fails closed badly). Treat `&` anywhere in a segment as mutating. `519cac7` | Closed the hole under the safety argument that verification concurrency rests on. |
| The batching prompt cut cost 67% **and cut investigation 32%** with it. Every sentence framed tool calls as expense, and the agent drew the obvious inference: the cheapest number of greps is zero. Grep went 6 → 0 on all four tasks. Falsification guidance carrying *no* cost framing later did the same thing — so the real variable is prompt *length* diluting the grounding paragraph. | Lead with grounding and reframe batching as what makes grounding affordable: *"use it to do the same checking in fewer turns, never as a reason to check less."* Drop the cost argument from `write_file` guidance. Add `tests/test_prompt_discipline.py`: no prompt may name an artifact of the tasks it was tuned on, verification guidance lives in the shared contract, correctness guidance carries no cost framing. `dd84d95`, `77c5c41` | Investigation recovered 25 → 35 calls (grep 0 → 3) while the batching win held (contract calls still 6, cost still 58% below baseline). Wall-clock did **not** recover: 656s → 1073s, worse than the 945s un-batched baseline. Treat prompt length as a budget. |
| Non-Anthropic providers return a flat `reasoning_content`, which we captured, logged and **dropped** — so a reasoning model re-derived its thinking every single turn. | Echo it back under `preserve_reasoning`, confirmed reaching the wire by prompt-growth arithmetic rather than assumption, with the cache holding (94.8% → 95.5%). `98c08aa` | Then measured, and **shipped off by default**: total reasoning flat (−1%), reasoning per turn −23%, turns +29%, cost **+59%**. It didn't make the model reason more — it spread the same reasoning over more turns. The 2/4 vs 1/4 reward rests on one task known to flip on identical code. |
| We assumed asking for more reasoning effort would get it. | Measured on `minimax-m2.5`: `medium` **lowered** thinking against leaving it unset — per-turn mean 265 → 200 chars, single-turn peak 1,644 → 719 — and the run went from 33 turns to the 60-turn cap at +160% cost. `harbor.yaml` therefore leaves it **unset**. `98c08aa` | `reasoning_effort` is a ceiling, not a floor. Don't set it blind; measure peak per-turn reasoning on the target model first. |
| `edit` was exact-match only. An `old_string` differing by whitespace, indentation or CRLF returned a bare "not found" and the model looped. An empty `old_string` reported a confusing "occurs N times". | Layered resolution: exact → strip pasted `read_file` line-number prefixes → normalize CRLF/LF → re-anchor flexibly on indentation. Unique-match-only; bails safely on ambiguity. Near-miss diagnostics say exactly what to fix. Add `multi_edit` for N atomic edits to one file. `18d3774`, `7f064ba` | Removed the most common cause of wasted turns. Directly targets the pattern where 48% of our tool-argument bytes came from 42 `write_file` calls averaging 6.2 KB. |
| `grep` didn't branch file-vs-directory, so grepping a single file or a symlinked path returned a silent "no matches" on GNU/BSD — and an unreadable path reported the same thing. Search wasn't gitignore-aware. | `-R` plus trailing-slash handling, an honest error on unreadable paths, `find -L` so glob follows symlinks, a shared lexical confinement resolver so read/grep/write reach in-workspace symlinks like bash does. Prefer ripgrep with a `grep -E` fallback in one shell command. `b598b55`, `7f064ba` | "No matches" started meaning no matches. |
| Large tool output was truncated and gone. | Store the full output in the session dir and inject a compact stub with a pointer; `buffer_grep` / `buffer_slice` / `buffer_list` retrieve it, and `buffer_query` runs a helper-model map-reduce over it. `b598b55`, `632f71d` | 58KB of output stays reachable. Live testing caught what review wouldn't: Gemini's ~1KB tool-call ids overflowed the filename limit, so buffer ids are short hashes. |
| The agent spent 2–5 turns at the start of every run discovering the OS, runtimes, package managers and git state. | Probe it once at session start in one bounded read-only command and fold the result into the first-turn prompt. `e791128` | Fewer wasted round-trips, no benchmark-specific machinery. |
| A timed-out bash command was killed but its children weren't, so orphaned `node`/`pytest` processes held ports after the run. Background task logs were written **inside the workspace**, polluting the `git diff` the verifier reads. | `start_new_session` + `killpg` locally; `setsid` for background tasks; container-side timeout so a command dies even when the exec client is torn down; logs moved to `/tmp`; kill leftover tasks at run end. `16a5275` | Clean workspace and no held ports at run end. |
| The background sweep tracked launches by a `pgrep -f` pattern rebuilt from the command text — assuming argv still resembles what was typed. On macOS `/usr/bin/python3 server.py` re-execs as `Python.app/Contents/MacOS/Python server.py`, which the pattern can't match. Separately, `kill -- -$pid` named the wrong group on macOS, where the launcher never led one. | Record the **process group** a backgrounding command leaves behind and use group membership as the evidence; keep the pattern as a second source for setsid/nohup launches. Re-probe after every signal — finding a pid was never evidence the signal landed. Report survivors separately instead of counting them as killed. `set -m` so each launch leads its own group. `f057fd5` | A server was being left holding its port while the run reported a clean workspace — and **whether it happened depended on `PATH`**, so the same test passed on one machine and failed on another. Verified against a `sleep` that outlived every kill before and none after. |
| The action memo could serve a cached filesystem read taken *after* a background launch, since `task_output` is non-mutating and nothing marked the file as changed. | Stop memoizing filesystem reads while a background task is live. A raw `cmd &` gets that permanently: nothing reports its exit, so there's no honest moment to resume caching. `f057fd5` | No stale reads of files a background process is writing. |
| The SSRF guard resolved the host, then handed the **hostname** to `urlopen`, which resolved it again. A short-TTL DNS record could answer publicly for the check and `169.254.169.254` for the connect. | Vet and dial one resolution: substitute the vetted IP at connection time while leaving `self.host` to drive SNI, cert validation and the `Host` header. Redirect hops get their own pre-flight so a refusal names the hop. `b4132a8` (base guard: private/loopback/link-local blocking, 45s deadline, 5MB cap, `0f75eb8`) | Closed textbook DNS-rebinding SSRF against cloud metadata. |
| A cloned repo's own `.agent/settings.yaml` could enable `load_project_tools` — which **imports** `.agent/tools/*.py` — and register hook shell commands that fire with no permission gate. Clone a repo, run the agent, run their code. Separately, the sandbox's own read/write bypassed the OS sandbox and used lexical-only confinement, so an in-workspace symlink escaped it. | Both flags read from **global** settings only; an explicit CLI/SDK flag still works per-run. Sandbox read/write re-resolves and re-checks. `cdb9b85` | Removed silent code execution on clone. |
| `garuda serve` on loopback required no auth and was reachable from a browser — unauthenticated host RCE. | Auto-generate and print a bearer token even for loopback (non-loopback requires an explicit one); constant-time compare; reject any request carrying an `Origin` header; 30s read timeout; malformed JSON returns `-32700` instead of dropping the socket. `3fba368`, `fb68dc8` | Closed browser-reachable RCE. |
| We tried to denylist host file reads under macOS Seatbelt and shipped docstrings implying it worked. | Verified empirically that it **cannot** be done: an unfiltered `(allow file-read*)` beats any later, more specific deny, and a read allowlist tight enough to matter breaks ordinary exec. Corrected the docstrings instead of shipping a placebo control, and surfaced the limitation at runtime. `cdb9b85` | Three trust mechanisms, honestly ranked: Docker is a confinement boundary, Seatbelt is a blast-radius reducer, permission rules are guardrails that screen arguments and never results. No design now assumes a guarantee that isn't there. |
| Three permission holes: a tool-level `ask` rule was **overwritten** by the command screen; the `allow_prefixes` fast path accepted shell-chained tails (`git status && curl \| bash` matched the trusted prefix); and `use_tool` invoked its target with no re-check, so per-tool MCP deny/ask rules were silently ignored in lazy-discovery mode. | Combine tool and command decisions with the stricter winning; make chained tails fall through to deny/ask; thread the permission engine into `ToolContext` and re-screen the target inside `use_tool`. `7fbdde8`, `cc39967` | Rules that were quietly no-ops started taking effect. |
| The tool registry was a process-global dict that runs *mutated*, so in a job server or batch eval one run's custom tool leaked into every other run in the process. | A `ToolRegistry` class: built-ins in one shared base, a per-run **layer** over it for custom or overriding tools. Module-level functions kept as shims for back-compat. `f134e7d` | Concurrent runs in one process stopped contaminating each other. |
| Each subsystem had its own hardcoded discovery paths — skills in `skills/` and `.skills/`, MCP elsewhere, profiles elsewhere again, `.garuda/` back-compat handled per-subsystem. | One `.agent/` project home holding `agents/`, `skills/`, `tools/`, `mcp.json`, `settings.yaml`, with `.garuda/` as an alias defined **once**. All discovery routes through `config/agent_home.py`; `~/.agent` is the global standard. `3ad3173`, `5471a4c` | Adding a discoverable thing is one change, not five. Subagents resolve project profiles the same way the top-level agent does. |
| Every MCP tool's schema was injected into the prompt, so twenty servers meant a prompt full of schemas the model would never call. | Above a threshold (default 10 tools), expose `search_tool`/`use_tool` instead of every schema. Below it, behaviour is unchanged. `584db6d` | N schemas collapse to 2. |
| `garuda serve`'s `run` was blocking and one-at-a-time: the connection was held for the whole agent run. `JobManager` also pruned only at submit, so a server that took a burst and went quiet held every event history indefinitely. | A job model — `submit`/`status`/`events` (cursor-based)/`result`/`cancel`/`jobs` — with background tasks gated by a concurrency semaphore. Prune on completion too, with a TTL on terminal jobs. A per-provider concurrency governor caps in-flight calls, acquiring a slot **per attempt** so a request sleeping on backoff releases its slot instead of starving the fleet. `e76ceab`, `b5a6594`, `f057fd5` | Many runs at once without blowing a provider's rate limit or leaking memory. |
| Two independent read-modify-write writers touched `meta.json`, so whichever replaced last dropped the other's fields — a finished run could lose its usage totals to a concurrent provenance patch. | Both go through one merge under an exclusive lock. The lock lives on a **sidecar** file, because publishing uses `os.replace` and locking the target would leave each writer holding a lock on a detached inode. Staging filenames are pid-scoped. `b4132a8` | Session metadata stopped losing writes. |
| `AgentConfig` had five gates that each cost a model call or a command re-run, and **all defaulted on** — so "just run this task" was priced like a graded benchmark. `--mode readonly` was also a no-op (nothing read it), and profile YAML couldn't set four of the five gates at all. | One selector implies a coherent set: `interactive` (default, no model-call gates), `eval` (the benchmark configuration), `rigorous` (eval + plan/execute/critic), `readonly`. Precedence: config defaults → mode preset → fields the profile *declared* → explicit CLI flags. The Harbor adapter pins `eval` explicitly, with a test asserting the pin. `b4132a8` | A bare `garuda run` pays for the work and local checks, nothing more. **What the cheap default costs in quality is unmeasured** — an ablation variant exists for exactly that comparison. |
| `DefaultAgent.run` was a ~500-line method doing setup, the turn loop and completion, with `_handle_task_complete` taking fifteen parameters. Every fix in any of those areas carried the blast radius of all three. | Split into five files with one job each: `loop.py` (the turn loop), `run_state.py` (assembly + carried state), `steering.py` (what the harness tells the model), `tool_runner.py` (executing calls), `completion.py` (the gate). `b4132a8` | `loop.py` **780 → 354 lines**. The public import surface still resolves from `core.loop`. |
| Docs were a status diary plus closed review ledgers that mixed open and closed items — so you couldn't tell what was left without re-auditing the code, which is what they were supposed to save you from. | `ARCHITECTURE.md` → `MODULES.md` → `BACKLOG.md`, everything else dated under `archive/` and marked unmaintained. The rule that makes BACKLOG work: **nothing in it is marked done** — if you fix it, you delete it. `b4132a8` | 4,794 lines → 305. |
| Cost was priced through litellm, whose cost map is **fetched from GitHub at import time** and revised upstream continuously — so the same trajectory could price differently on two machines on the same day, and our tests effectively asserted on someone else's repo. Dependencies were unpinned. | A versioned in-repo price snapshot answers first; litellm fills gaps with its network fetch **disabled**; tests use a fixture table. `constraints.txt` pins tested versions — CI's gating job installs with it, a non-blocking latest-deps job installs without. `f057fd5` | Cost numbers became reproducible, and an upstream break opens an issue instead of blocking an unrelated PR. |
| We had no per-turn timing, so every wall-clock figure was assembled by hand. | Record model latency, tool time vs tool wall-clock, compaction, checkpoint and cache-hit rate; roll up to the result and emit a `turn_metrics` event. Document two traps: `model_ms` includes retry/backoff on purpose, and `parallel_saved_ms` measures overlap, not end-to-end improvement. Fixed a bug where overflow recovery booked compaction time to the provider. `1df4617`, `519cac7` | Latency decisions can now be made on numbers. Nothing has been re-measured with it yet. |
| An external review hit 4 test failures on a different macOS host — 3 were live `sandbox-exec` tests whose behaviour varies by OS version. Two other tests had no fault-detection power at all (a tautological `isinstance` check; asserting a tool registered at import is registered). | Gate every test that actually invokes a sandbox behind `GARUDA_LIVE_SANDBOX=1`; check Docker daemon *reachability*, not CLI presence; use `sys.executable` and absolute fixture paths. Delete the powerless tests, replace with a real end-to-end job-pipeline test. `029fa77`, `66a9aef`, `cdb9b85` | CI green on any host, and the suite tells you something when it passes. |

## Where this leaves us

Tests 49 → 1,049. `loop.py` 780 → 354 lines. Docs 4,794 → 305 lines. Context budget
error −24.6% → +4.7%. Contract calls on a 4-task sample 79 → 6, cost $0.348 → $0.145.

Still open, in [BACKLOG.md](BACKLOG.md): the LLM verdict approves incorrect work
(4 false positives across 16 tasks, and it *is* the run's answer); better evidence
hasn't converted to reward anywhere, because the gate can force a check that *can*
fail but not the check the grader makes; the final turn can nudge but cannot force a
commit; and **nothing has been run twice** — which is the most valuable next
experiment.
